# Squadio — סטטוס אפליקציה נייטיב + צעדים הבאים

מצב נוכחי: אפליקציית אנדרואיד (Capacitor) שרצה מול **השרתים הקיימים**, בלי שום שירות חדש.
ה-APK נבנה ב-GitHub Actions (ענף `feat/native-app`, workflow `apk.yml`, artifact `squadio-apk`).

---

## ✅ מה שעובד באפליקציה עכשיו (שרתים קיימים, בלי שירות חדש)
- לוח ההורים/מפעיל, מסך ניהול מלא (כניסה, טיוטה, פרסום, באנרים, אישורים, לינקי הזמנה).
- הרשמה (`/join/...`), ריבוי-קבוצות, ריבוי-מועדונים + מעבר בין מועדונים.
- ניווט בין המועדונים ותתי-הדומיינים נשאר **בתוך** האפליקציה (`allowNavigation`).
- לינקים חיצוניים (וואטסאפ / מפות / יומן) נפתחים באפליקציות המערכת.

> האפליקציה כרגע **טוענת את האתר החי** בתוך קונכייה נייטיב. באנדרואיד האחסון של ה-WebView
> קבוע (לא נמחק כמו ב-PWA באייפון), אז בעיית "נרשם כל פעם מחדש" לא קיימת כאן.

---

## 🛑 דורש שירות חדש — פה עצרנו (לפי ההנחיה)

### 1. התראות פוש
אפליקציה נייטיב לא מקבלת Web Push; צריך את הערוצים הנייטיביים:
- **אנדרואיד → Firebase Cloud Messaging (FCM)** — פרויקט Firebase חדש (חינמי).
- **אייפון → Apple Push Notification service (APNs)** — דורש **Apple Developer Program** (‏$99/שנה).

**צעד-אחר-צעד (כשנחליט להמשיך):**
1. צור פרויקט ב-Firebase → הוסף אפליקציית Android עם package `com.squadio.app` → הורד `google-services.json` ל-`android/app/`.
2. התקן `@capacitor/push-notifications`; הוסף רישום טוקן ומאזין בצד הלקוח.
3. בשרת הקיים: הוסף שליחה ל-FCM (עם Server Key / HTTP v1) **לצד** `web-push` הקיים; הרחב את טבלת `push_subscriptions` בסוג-טוקן + פלטפורמה, וה-broadcast יבחר ערוץ.
4. לאייפון: פתח חשבון Apple Developer, הגדר APNs Key, חבר ל-Firebase (או שלח ישירות ל-APNs), והוסף את הרשאת הפוש ל-iOS.

### 2. (רק לאייפון) חשבון Apple Developer
בלי זה אי אפשר לבנות/להפיץ iOS ולא APNs. ‏$99/שנה. חד-משמעית שירות/חשבון חדש.

## ⚠️ מגבלות WebView — *לא* דורש שירות חדש, אבל צריך אינטגרציה נייטיב (תוספי Capacitor)
אלה לא "שירות חדש", רק עבודה טכנית שלנו. כדאי לבדוק על מכשיר ולתקן בהמשך:
- **הורדת קבצים** (ייצוא לוח ל-Excel / ICS מהניהול): WebView לא תמיד מטפל בהורדת blob. פתרון: `@capacitor/filesystem` + `@capacitor/share` (בלי שירות חדש).
- **שיתוף/העתקה** (כפתורי "שתף בוואטסאפ" / "העתק קישור"): לרוב עובד, אבל במקרי קצה כדאי `@capacitor/share` / `@capacitor/clipboard`.
- **עבודה אופליין**: טעינה מרחוק דורשת רשת. יפתר כשנעבור ל-build ארוז (ראה למטה).

---

## 🧱 מעבר לאפליקציה "ארוזה" אמיתית (אופציונלי, בלי שירות חדש)
היום האפליקציה טוענת את האתר מרחוק. כדי שתיטען **מקומית** (מהירה, פחות תלות ברשת):
1. להפנות את כל קריאות ה-API לכתובת מוחלטת (`API_BASE`) דרך עטיפת `fetch` אחת.
2. להוסיף **CORS לשרת הקיים** (שינוי קטן ובטוח בשרת שכבר יש — *לא* שירות חדש) כדי לאשר מקור נייטיב.
3. להסיר את `server.url` מ-`capacitor.config.json` ולהשתמש ב-`webDir: dist` הארוז.
4. אחסון זהות נייטיב (`@capacitor/preferences`) + רשימת מועדונים + מעבר מועדון.

## 📲 פרסום לחנויות (שלב עתידי)
- **אנדרואיד (Play):** AAB חתום במפתח release (keystore) — יש כבר תבנית ב-SportDle (`release.yml` + סודות `KEYSTORE_*`). עלות: ‏$25 חד-פעמי.
- **אייפון (App Store):** בנייה ב-macOS/Xcode או שירות ענן (Codemagic/Appflow), + חשבון Apple Developer.

---

## איך בונים APK עכשיו
- אוטומטי: כל push לענף `feat/native-app` מריץ את `apk.yml`.
- ידני: GitHub → Actions → "APK" → Run workflow.
- הורדה: הריצה → Artifacts → `squadio-apk` → `app-debug.apk` (sideload לטלפון).

## סדר עבודה מוצע להמשך
1. לבדוק את ה-APK על מכשיר אמיתי: לאמת מה עובד, ולסמן הורדות/שיתוף.
2. להחליט על פוש → להקים FCM (אנדרואיד) כשלב ראשון (חינמי), iOS בהמשך עם Apple Developer.
3. (אופציונלי) מעבר ל-build ארוז + CORS.
4. חתימת release + פרסום לחנויות.
